AWS does not run one giant data center. It spreads capacity across the globe in
a structure you should be able to draw from memory: Regions contain Availability
Zones, and a separate network of edge locations sits closer to users. This
layout is what lets you build applications that stay up when part of the
infrastructure fails.

## Regions

A Region is a physical location in the world where AWS clusters data centers.
Each Region is a separate geographic area, such as one in Northern Virginia and
another in Ireland. Every AWS Region is made up of multiple Availability Zones,
and AWS states that each Region has a minimum of three that are isolated and
physically separate from one another.

You choose which Region your resources run in. Data and services you place in a
Region stay in that Region unless you move them, which matters for the
compliance discussion below.

## Availability Zones

An Availability Zone, or AZ, is one or more discrete data centers with redundant
power, networking, and connectivity inside a Region. The AZs in a Region are
physically separated by a meaningful distance, far enough apart that a single
event such as a flood or a power outage is unlikely to hit more than one, yet
connected by high-bandwidth, low-latency links so they can work together.

That separation is the point. Running across multiple AZs lets you operate
applications and databases that are more highly available and fault tolerant
than you could from a single data center. If one AZ has a problem, the copies of
your workload in the other AZs keep serving.

<Callout type="key" title="Region versus Availability Zone">
A Region is a geographic area. An Availability Zone is one or more isolated data
centers inside that Region. High availability comes from spreading a workload
across several AZs in the same Region, so one AZ failing does not take you down.
</Callout>

## Edge locations and Amazon CloudFront

Edge locations are a separate, much larger set of sites, distinct from Regions
and AZs. Amazon CloudFront, the AWS content delivery network, uses them. When a
user requests content, CloudFront routes the request to the edge location that
gives the lowest latency and serves a cached copy from there. If the content is
not cached at that edge location yet, CloudFront fetches it from the origin, such
as an Amazon S3 bucket or a web server, and caches it for the next request.

The benefit is distance. Holding copies of files at edge locations around the
world means a user's request travels a shorter path, which lowers latency and
speeds up delivery.

## AWS Global Accelerator

AWS Global Accelerator also works from the edge, but it solves a different
problem. It gives you static IP addresses, anycast from the AWS edge network,
that act as one fixed entry point for your application, then routes traffic over
the AWS global network to the optimal regional endpoint based on endpoint health
and where the client is. That suits applications running over TCP or UDP, such
as online gaming and voice over IP, and any case that needs a fixed address or
fast failover between Regions. The difference from CloudFront is what happens at
the edge: CloudFront caches HTTP content there, while Global Accelerator proxies
packets on to your endpoints in a Region.

## AWS Local Zones

An AWS Local Zone is an extension of an AWS Region in geographic proximity to
your users. It places compute, storage, database, and other select AWS resources
close to large population and industry centers, so nearby users get low-latency
access. AWS gives two reasons to use one: running low-latency applications at the
edge, such as real-time gaming, live streaming, and virtual workstations, and
meeting stringent state and local data residency requirements in sectors such as
healthcare, financial services, and government. A Local Zone belongs to a parent
Region rather than replacing it.

## Choosing a Region

Four factors usually decide which Region to deploy in:

- Latency and proximity. Pick a Region near your users so requests travel less
  distance and responses arrive faster.
- Compliance and data residency. Some laws require data to stay within a
  country or area. Because resources stay in the Region you choose, you select a
  Region that meets those rules.
- Service availability. Not every AWS service or feature is available in every
  Region, and the services-by-Region list changes over time. Check the AWS
  Regional Services List for the Region you want.
- Pricing. Prices vary by Region, so the same resource can cost more in one
  Region than another. Cost can be the deciding factor when the others are equal.

<Callout type="note" title="No single right answer">
Region choice is a trade-off. A Region close to users might lack a service you
need or cost more, while a compliant Region might add latency. Weigh the four
factors against what the workload actually requires.
</Callout>

## Disaster recovery

Multiple Availability Zones in one Region already mitigate events like fires,
floods, and major power outages. Planning past that starts with two numbers. The
recovery time objective, or RTO, is the maximum acceptable delay between the
interruption of service and restoration of service. The recovery point objective,
or RPO, is the maximum acceptable time after the last data recovery point, which
is how much recent data you can afford to lose. Choosing a strategy trades
reduced downtime and data loss against cost and complexity.

AWS lists four strategies in increasing order of cost and complexity and
decreasing order of RTO and RPO:

- Backup and restore. Back data up to a recovery Region and redeploy when
  needed. Least complex, lowest cost, longest recovery time. Define the
  infrastructure as code with AWS CloudFormation so it redeploys quickly and
  without errors, back up configuration and application code as well as data,
  and test the restores.
- Pilot light. A copy of the core infrastructure and replicated data sit in the
  recovery Region, with the rest switched off.
- Warm standby. A scaled-down but fully functional copy runs all the time in the
  recovery Region.
- Multi-site active-active. The workload runs in several Regions and serves
  traffic from all of them, which can bring recovery time near zero at the
  highest cost and complexity.

Pilot light cannot process requests until you act first, while warm standby takes
traffic at reduced capacity immediately. That is the line between the two.

## What to take away

Know the hierarchy: Regions are geographic areas, each with at least three
isolated Availability Zones, and edge locations form a separate global layer for
caching through CloudFront. Resilience comes from spreading a workload across
AZs. Region selection comes down to latency, compliance and data residency,
service availability, and price. Global Accelerator adds a static edge entry
point, Local Zones push a Region closer to users, and the four disaster recovery
strategies trade cost and complexity against recovery time.
